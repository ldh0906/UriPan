## 두 세션 수렴점

BE와 PM/UX가 독립적으로 같은 결론에 도달:

### 데이터 모델 — 하이브리드
- `board_item_recurrences`(반복 *규칙*만) + `board_items`에 occurrence 행을 **rolling window로 materialize**.
- 순수 on-the-fly 계산 탈락(occurrence별 `is_done`·댓글·알림 id·realtime·deep link 애매). 전체 materialize 탈락(행 폭증).
- **규칙은 local wall-clock**(timezone + frequency + weekday/month_day + local_time)로 저장. **occurrence의 `starts_at/due_at`만 기존대로 UTC `timestamptz`** → 기존 round-trip 규칙과 충돌 없음.
- v1.3 패턴 재사용: `board_id` 비정규화, RLS `is_board_member(board_id)`, realtime 필터, `replica identity full`. 클라는 계속 `board_items:board_id`만 구독.
- 생성/수정/rolling은 **RPC**(`create_recurring_board_item` / `update_recurring_board_item` / `ensure_recurrence_occurrences`). v1.4는 앱 시작·보드 진입 시 클라가 window(약 45일) 채움. 서버 cron(Edge Function)은 v1.5+.
- seed item = 사용자가 만든 첫 `board_items` 행(숨겨진 template row 금지 → 구버전 클라 호환). 신규 컬럼 nullable → backfill 불필요.

### 제품 범위
- 빈도: **매일 / 매주 / 매월 + 종료일 필수**. 무기한·격주·복수요일·n번째요일 제외.
- 수정/삭제 = **시리즈 전체만**. "이 회차만 / 이후 전체"는 금지(예외 모델이라 MVP 정면 충돌).
- 공지(notice) 반복 제외.
- 알림 **로컬만**(기존 30일/60건 캡 안에서 펼침). 푸시는 `notification_events` 큐 설계만 보관, v1.4 제외.

### UX
- 작성/편집 시트에 일정/할 일 한정 "반복" 섹션(반복 안 함/매일/매주/매월 → 종료일). 요일·기준일은 시작일에서 자동 결정.
- 저장 전 **반복 요약 문장**("매주 수요일, 2026.12.31까지")이 저장 규칙과 1:1 일치 = v1.3 "보이는 값=저장되는 값" 계승.
- 카드 `반복` 배지, 편집/삭제 진입 시 "이 반복 전체를 수정/삭제합니다" 명시.

## 의장 확정 결정 (2026-06-14, PM=사용자)

1. **반복 할 일 완료 = 회차별 독립 완료.** "매일 설거지"는 오늘 완료해도 내일 다시 미완료. → occurrence를 `board_items` 행으로 materialize해야 하는 근거. (BE가 "가장 위험한 가정"으로 지목했던 항목을 명시 확정)
2. **월말 정책 = 그달 마지막 날로 clamp.** 매월 31일 반복 → 2월은 28/29일, 4월은 30일. 서버 고정 정책(`month_day_policy='clamp_to_last_day'`), UI 옵션 없음.
3. **시리즈 삭제 시 과거 occurrence는 기록으로 보존, 미래만 삭제.** "반복 끝내기"는 종료일 앞당김으로 표현.

## 가장 위험한 가정 / 함정 (BE)
- 절대 UTC instant에 7일/1개월을 더하지 말 것. 항상 **local date 먼저 계산 후 timezone 변환**.
- `Asia/Seoul`은 DST 없어 단순화 가능하나, 기기 timezone 변경 시 `toLocal()` 필터가 보드 날짜와 어긋날 수 있음. v1.4 공식 지원 timezone은 `Asia/Seoul`로 제한(컬럼은 IANA 이름 저장).
