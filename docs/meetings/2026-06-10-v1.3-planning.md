## 교차 검토에서 드러난 수렴점

여러 참석자가 독립적으로 같은 항목을 짚었다 — 우선순위 신호로 해석:

1. **연기된 QA 3건(A2/C2/C3)을 v1.3에서 해소** — PM #4·#5, BE #1·#2·#3이 모두 지목. BE가 구체적 마이그레이션 설계까지 제출:
   - QA-C2: `board_id` nullable 추가 → backfill → not null → 트리거(구버전 클라가 board_id 없이 insert해도 트리거가 채움) → RLS `is_board_member(board_id)` 단순화 → realtime 필터
   - QA-A2: `*_name_snapshot` 컬럼 + before insert/update 트리거, "작성 당시 이름 보존" 정책 권장. UX는 "민준 · 나감" 식 표시 제안
   - QA-C3: `alter publication supabase_realtime add table boards` (idempotent 패턴) + `joined_at` 불변 트리거 동일 배치
2. **반복 일정** — PM 1순위 + BE #5가 스키마(`board_item_recurrences`, occurrence rolling window) 제시. 단 BE는 timezone/DST 리스크로 "스키마 기반부터"를 권고
3. **푸시 알림 인프라** — PM #3 + BE #5 모두 제안하나 둘 다 운영 복잡도(FCM/APNs, Edge Function, 토큰 관리)를 경고. **v1.3 범위에서 제외 권고**
4. **CI 부재** — QA #3: `.github` 워크플로 없음, "162개 통과"가 로컬 상태에 의존. 난이도 S로 효과 대비 비용 최소
